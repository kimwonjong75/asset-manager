# 터틀 홈·보유자산·설정 수정 계획안

2026년 11월 21일 · 1~3차 프런트엔드 구현 · 변경 전 기준 커밋 `7ba4373`

홈·설정·보유자산·CSV·차트 변경을 로컬 앱에 반영했다. 시세 거래일은 서버가 제공한 날짜를 사용하며, 구형 데이터와 날짜가 누락된 응답은 ‘미확인’으로 표시한다. 서버 RSI 산식은 별도 백엔드 확인 대상이다. 계좌 MDD는 외부 입출금과 과거 보유분의 계정을 식별할 이력이 확보될 때까지 후속 과제로 둔다.

**목표는 홈을 한 번 보고 내 종목에 규칙이 적용됐는지, 오늘 무엇을 확인할지 아는 것이다.** 평소에는 결과 한 줄이면 충분하다. 신호가 있거나 검사하지 못한 종목이 있을 때만 이유와 다음 행동을 보여준다.

|---|---|---|

## 2차 · 홈에서 내 종목 확인하기

### 홈 첫 줄과 버튼

기본 화면에는 적용 계정과 결과 한 줄을 둔다. 아래 숫자는 **표시 예시**다. 신호와 자료 누락이 함께 있으면 둘 다 표시한다.

| 실제 상태 | 화면 문구 예시 | 누르면 열리는 곳 |
|---|---|---|
| 대상 18개 판정 완료, 신호 없음 | 오늘 터틀 매매 신호 없음 · 18종목 확인 완료 | 적용 대상·제외 사유 상세 |
| 8개 매도 기준 도달 | 터틀 매도 기준에 닿은 종목 8개 | `매도 대상 확인` → 기존 터틀 정리 |
| 16개 완료, 2개 시세 누락 | 16종목 확인 완료 · 2종목은 시세 확인 필요 | 해당 종목과 확인 불가 사유 |
| 전부 가족 계정 또는 설정에서 제외 | 현재 터틀 적용 대상 없음 | `적용 범위 보기` → 설정의 터틀 규칙 |
| 매매 신호는 없고 손절 예약주문 점검 1건 | 오늘 터틀 매매 신호 없음 · 손절 주문 확인 1건 | 해당 포지션의 손절선 |

- 모바일에서 신호가 많은 구역은 **두 종목**을 먼저 보여주고 `나머지 6개 보기`처럼 전체 목록을 연다. 신호가 없는 구역의 반복 문구는 접는다. 차트, 종목 검토, 현재 재진입 기준선·기준일은 펼친 상세에서 이어 본다.
- 매도는 기존 ‘터틀 정리’에서 체결 후 기록한다. 보류는 해당 종목에 제공되는 기존 절차를 따른다. 재매수와 추가매수는 해당 종목의 기존 계산기를 연다.
- 보유 종목과 관심종목 감시 건수를 상세에서 구분한다. 같은 종목이 추가매수와 손절선 점검에 모두 나타나면 두 행동은 표시하되 검사 종목 수는 한 번만 센다. 이미 보유해 중복 제외된 관심종목도 제외된 보유분으로 세지 않는다.

### 종목이 빠진 이유와 현재 규칙

- **“현대차는 왜 안 보이지?”** 보유자산의 ‘터틀 상태’를 누르면 가족 계정, 개별 종목 제외, 자산군 제외, 시세 조회 실패 등 실제 이유가 나온다. PC 기본값은 이 열이 숨겨져 있으므로 홈의 적용 대상 상세에서 `보유자산 → 보기 → 컬럼 설정 → 터틀 상태` 경로를 안내한다. 기존 사용자 열 구성을 존중하고, 모바일에서도 제외된 종목의 사유를 확인할 수 있게 한다.
- **“50일선에 팔면 다시 언제 사지?”** 설정과 홈의 규칙 상세에 저장값을 읽어 `매도 50일 이동평균 · 재매수 직전 55일 최고가 돌파`처럼 한 줄로 쓴다. 이 숫자는 예시다. 코어 6종 MA50 실험에서 쓴 ‘50일선 재돌파’와 앱의 재진입 방식이 다르다는 설명을 해당 실험 결과에 붙인다.
- **“일봉이 충분한데 왜 확인 불가인가?”** 기존 보유분의 ATR 추적선은 계산에 추적 시작점이 전달되지 않는다. 이때는 ‘ATR 추적 시작점을 확인할 수 없음’으로 표시한다. 진입일이 확인되는 재매수 포지션과 실제로 일봉이 부족한 사례를 따로 검사한다. 임의 날짜에서 추적을 시작하면 매도 신호가 바뀌므로 이번 표시 수정에서는 날짜를 추정하지 않는다.

## 구현·검수 순서

1. **1차를 먼저 독립 검수한다.** 앞선 검토와 같은 예시 데이터로 PC 1440×900, 모바일 390×844에서 버튼을 직접 누르고, 설정을 편집·이동·복귀·저장한다. 모바일 하단 탭과 저장 영역이 겹치지 않는지 확인한다.
2. **2차는 판정 모델부터 고친 뒤 홈과 보유자산에 함께 연결한다.** 전체 제외, 전체 실패, 부분 성공, 매도 신호와 시세 실패 동시 발생, 추가매수와 손절 점검 중복, ATR 시작점 누락을 검수한다. 모바일에서 숨긴 행을 펼쳐 모든 종목에 도달할 수 있어야 한다.
3. **3차는 소유 계정, 실제 거래일, 산식 순으로 확인한다.** CSV 계정 열은 먼저 적용할 수 있다. 거래일·산식이 프런트에 제공되지 않는 경로는 서버 응답을 확인한 뒤 연결한다.
4. **각 차수의 코드 수정 직후 해당 파일의 책임·입력·예외 처리를 `RULES.md`에 반영한다.** 집계와 판정은 훅·순수 함수에서 처리하고 화면은 결과를 렌더링한다. PC 표와 모바일 카드를 함께 확인한다. 변경한 사례를 기존 테스트에 반영하고 `npm test`, `npm run build` 및 위 화면 검수를 수행한다.
