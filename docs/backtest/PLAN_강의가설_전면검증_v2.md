## 1. 두 검토의 교차 비교 결과

두 AI 검토(Claude 1차 실행분 / 외부 AI 재검토)를 대조하고, 검증 가능한 기술 주장은 코드·데이터로 직접 확인했다.

### 1-1. 외부 AI 지적이 **맞았던 것** (실제 결함 — P0에서 보수)

| # | 지적 | 검증 결과 |
|---|---|---|
| A | §5.6 필수 팩터 중 **5일 상승률(R5)·20일 변동성**이 계산만 되고 분해표에서 누락 | **확인됨.** `factorPanel.ts:160,165`가 `ret5Tertile`·`vol20Tertile`을 만들지만 `pipeline.ts:176-187`의 축 배열에 없음 → 사전등록 §5.6 위반 |
| B | 결과 문서가 계산된 분해를 대부분 공개하지 않음(시총·연도만) | **확인됨.** JSON엔 10축이 있으나 마크다운엔 2축만 게재 |
| C | `REVIEW_WARNING`은 앱 적용 준비 완료가 아님 — 기존 앱 규칙 대비 증분(C/D 반사실) 미검증 | **맞음.** 1차에서 C/D를 의도적으로 생략했음. 앱 적용 판단에는 필수 |
| D | 잠금표본 미개봉 상태에서 최종 채택 선언 불가 | **맞음.** G8·G11 미통과로 봉인 유지 중 |
| E | 순서: RS90 매수 품질 검증이 앱 적용보다 선행돼야 함 | **맞음.** 강의 핵심 블록이 미실행 |

### 1-2. 외부 AI 지적 중 **근거가 틀린 것** (결론은 유지, 처방이 달라짐)

| 지적 | 실제 |
|---|---|
| "S5 프록시가 앱과 불일치 — 앱엔 거래대금이 없고 20일 거래량 값만 있다(`types/api.ts:41`)" | **근거 오류.** `types/api.ts:41`은 종목 요약 `Indicators`이고, 앱은 별도로 `/history`에서 **종가·시가·고가·저가·거래량 시계열 전체**를 받는다(`services/historicalPriceService.ts:37-40, 52-58`). 따라서 63일 `종가×거래량` 최대 판정은 앱에서 **계산 가능**하다. |
| | **단, 결론(“앱 적용 근거로 아직 부족”)은 유지된다.** 진짜 위험은 데이터 부재가 아니라 **조정 기준 불일치**다 — 백테스트는 `adj_close×adj_volume`(분할조정), 앱 `/history`는 조정 여부가 미확인이다. 처방은 "데이터 확보"가 아니라 **"앱 입력 규약과 동일한 3번째 변형 추가 + 조정 기준 확인"**이다. |

### 1-3. 내 1차 보고의 미흡함 (자기 지적)

- 룩어헤드는 잡았지만 **§5.6 축 누락(A)은 놓쳤다.** 사전등록 준수 점검을 항목별로 하지 않은 탓이다.
- 10축 분해를 계산해 두고 문서엔 2축만 실었다(B). "검토했다"는 표현이 과했다.
- S5 프록시 결론을 "앱 이식 장애물 제거"로 읽힐 수 있게 썼다. 실제로는 **백테스트 내부 동등성**만 보인 것이고 앱 런타임 동등성은 미검증이다.

### 1-4. 두 검토가 일치한 것

1차 배치(D1 시장레짐 기각 / D2 급성매도 6종 통과)는 **폐기 대상이 아니라 유효한 1차 자료**다. 다만 이것만으로 앱 적용을 결정할 수 없다. 강의의 최대 블록인 **RS90 매수 품질**을 포함해 다수가 미실행이다.

## 3. 실행 단계

### P0. 1차 배치 결함 보수 (선행)
1. `pipeline.ts` 분해 축에 `ret5Tertile`·`vol20Tertile` 추가 → §5.6 11축 완비
2. 결과 문서에 **전 축 분해표 게재**(시장/시총/유동성/거래량배수/R5·R21·R63/1일수익·1일충격/vol20·vol63/레짐)
3. **S5 세 번째 변형 `S5_APP_RUNTIME` 추가**: 앱 `/history` 입력 규약(무조정 종가×거래량, 앱과 동일한 창)으로 판정. 기존 `S5_AMOUNT`(원천)·`S5_APP_PROXY`(조정가×조정거래량)와 3자 비교 → 앱 이식 시 신호 일치율을 정량화
4. D1·D2 재실행, 문서·JSON 갱신

### P1. RS 엔진 + 매수 품질 (강의 핵심)
RS 계산기 신규 구축 → RS90 진입 이벤트 → C1~C9 개발표본 스크리닝(Holm, 방향 일관성, 단조성) → 생존 특성으로 품질점수 → 검증표본 1회 확인 → A11·A12 부수검증

### P2. 보유 열화 + 런치패드
A7~A10 이벤트 스터디 + C11 런치패드 매수가설

### P3. 자산배분
D1~D5 5전략 비교. **채권 ETF 8종 티커 미확정 → 가정 티커로 실행하고 가정을 문서 최상단에 명시.** 사용자 확인 후 재실행 가능

### P4. 기존 앱 규칙 대비 증분 (앱 적용 판단의 필수 근거)
- C: 현재 앱 매도규칙만 / D: 앱 규칙 + 신규 통과 신호
- 비교 지표: 수익률, MDD, 불필요 매도(false sell), 재진입 비용, 세금, 신호 중복 처리
- **주의**: 앱 규칙을 백테스트에서 재현하는 것이므로 패리티 위험이 있다. 재현 코드는 앱 로직을 읽어 백테스트 측에 독립 구현하고, **동일 날짜·동일 종목 신호 일치율**을 함께 보고한다

### P5. 잠금표본 + 미국
- 잠금(2023-2025): G8(합병대가)·G11(KRX 교차검증) 통과 필요 — **현재 차단**
- 미국: PIT 유니버스·상장폐지·조정일봉 확보 필요 — **현재 차단**

### 앱 적용 (이 계획의 범위 밖)
P0~P4 결과를 항목별로 제시하고 사용자가 선택한 것만 별도 승인 후 구현한다. 자동매도는 어떤 경우에도 이번 범위가 아니다.
