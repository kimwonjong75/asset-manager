# 통합 리스트의 보유자별 잔고와 거래

2026년 11월 26일 · 구현 계획

통합에서는 같은 종목을 한 줄로 보여주고, 잔고와 매매는 원종·유선 각각의 자산 ID로 관리한다. 기존 `Asset.owner`와 통합·원종·유선 필터를 활용한다. 종목명은 상품을 식별하는 데 쓰고, 보유자는 이름과 수량으로 표시한다.

## 1. 리스트에서 바로 확인할 내용

아래 수량은 화면 설명을 위한 가상 예시다.

| 종목 | 보유자별 수량 | 합계 |
|---|---|---:|
| A ETF | 원종 12주 · 유선 8주 | 20주 |
| B 주식 | 원종 5주 | 5주 |
| C 주식 | 유선 3주 | 3주 |

- PC에서는 종목명 옆에 보유자별 수량을 항상 표시한다. 모바일에서는 카드명 바로 아래에 같은 내용을 둔다. 색상은 보조로 쓰고 이름과 단위를 표시한다.
- 기존 `통합 / 원종 / 유선`을 유지한다. 통합에서만 쓸 수 있는 `함께 보유만` 필터를 제공한다. 개인 보기의 수량·평가액·손익·정렬은 해당 사람 기준이다.
- 행을 펼치면 각자의 평단, 평가액, 손익과 매수·매도 버튼이 나온다. 통합 평가액과 손익은 개인별 금액을 같은 기준 통화로 환산해 합산한다. 통합 수익률은 합산 손익을 합산 원가로 나눈다.
- 주식·ETF의 묶음 기준은 정규화한 거래소와 티커다. 원통화·수량 단위가 어긋나는 자료는 확인 대상으로 둔다. RP는 통화·상품·기간·단위가 맞는 경우에 묶고 금액 단위로 표시한다. 식별 정보가 부족한 자산은 개별 표시한다.
- 합계 행은 화면에서 계산한다. 평가 총액, 전략 계산, 저장, 편집, 일괄 작업은 실제 개인별 자산 ID를 사용한다. 개인별 매매 계획과 알림은 해당 보유분을 펼쳐 확인한다.

## 2. 거래할 때의 흐름

| 시작 위치 | 매수 | 매도 |
|---|---|---|
| 통합 종목 행 | 두 명 중 매수자를 선택한다. 기존 보유자는 추가매수, 처음 사는 사람은 새 보유분을 만든다. | 매도 가능한 사람과 잔고를 보여준다. 둘 다 보유하면 직접 선택하고, 한 명만 보유하면 그 사람을 미리 표시한다. |
| 개인 보기 또는 개인별 상세행 | 해당 보유자를 미리 표시한다. | 해당 보유자의 매도 가능 수량을 표시한다. `전량`은 그 사람의 잔고 전체다. |

예를 들어 A ETF에서 유선이 3주를 매도하면 확인 버튼에 `유선 · 3주 매도 기록`을 표시한다. 저장 전 미리보기는 `유선 8 → 5주 · 원종 12주 · 합계 17주`가 된다. 유선이 남은 5주도 팔면 통합 리스트에는 원종 12주가 남고 유선의 매도 두 건은 개인 거래내역에 남는다. 두 사람이 같은 날 거래했다면 사람마다 한 건씩 기록한다.

첫 매수·추가매수·매도에는 거래 ID, 거래 당시 보유자, 자산 ID, 종목 식별 정보, 거래일, 수량, 단가, 통화·적용 환율을 저장한다. 매도 원가와 실현손익은 선택된 보유분 기준이다. 수량은 저장 시점에 다시 검증하고, 잔고와 거래기록을 같은 변경으로 저장한다. 동일 거래 재시도는 같은 거래 ID로 처리한다. 기존 매도기록은 확장하고 매수기록을 추가해 한 거래내역에서 조회한다. 전량 매도 뒤에도 양쪽 기록이 남아야 한다.

## 3. 기존 공동 표기 옮기기

1. 현재 데이터를 백업하고 이름·별칭·메모에 두 사람 이름이 모두 들어간 행을 추린다. 예전 자동 분류가 이미 유선으로 지정한 행, 같은 종목의 개인별 행이 따로 있는 경우까지 미리보기에서 확인한다.
2. 종목별로 기존 앱 수량, 두 사람의 명세서 수량, 기준일과 차이를 나란히 표시한다. 명세서 날짜가 다르면 사이의 거래를 반영해 같은 기준일로 맞춘다. 거래소·티커를 확인하고 이름만 유사한 다른 상품은 개별로 둔다.
3. 기존 총수량과 두 사람의 합이 맞고, 기존 개인별 행과의 중복을 해소한 종목부터 확정한다. 개인별 평균매입가와 외화 매입환율은 별도 보유·거래 자료로 확인한다. 잔고증명서의 평가단가는 취득원가를 알려주지 않는다. 수량만 확인되면 분할안을 임시 보관하고 원가 확인 전까지 기존 원금과 손익을 보존한다.
4. 확정 시 기준일의 시작 잔고로 나눈다. 분할 자체는 매매 건수·거래금액·실현손익 집계에서 제외한다. 이전 합산 ID와 새 개인 ID의 연결을 남기고 과거 스냅샷·거래는 원래 기록으로 보존한다. 보유자 귀속을 확인할 수 없는 과거 내역은 통합 이력에 `보유자 미확인`으로 표시한다. 옛 이름과 별칭은 분할 확인 후 정리한다.

## 4. 구현 순서와 완료 기준

| 순서 | 구현 범위 | 통과 조건 |
|---|---|---|
| 1. 공동 표기 점검과 통합 리스트 | 기존 잔고를 읽어 확정된 보유분만 종목별로 묶는다. 공동 표기 후보는 `분할 확인 필요`로 표시한다. 개인 보기와 모바일 카드에도 반영한다. | 공통·단독 보유가 펼침 없이 구분된다. 미확정 물량이 개인 물량으로 표시되지 않고 통합 총액에는 한 번만 포함된다. |
| 2. 보유자 지정 거래 | 신규 등록, 추가매수, 매도, 관심종목 매수와 기존 전략 실행의 저장 경로에 거래 당시 보유자를 전달한다. 수동 거래는 두 사람 모두 가능하며 원종 전용 전략은 원종 잔고만 사용한다. | 한 사람의 잔고를 넘는 매도는 차단된다. 미보유자의 첫 매수, 공동 보유자의 부분·전량 매도, 기존 매도 정정, 재시도 후 수량·기록이 일치한다. |
| 3. 실제 자료로 분할 적용 | 이전 미리보기에서 확인된 종목부터 분할하고 거래내역, Drive 저장·재로드, 백업 복원, CSV 계정 열 왕복을 검증한다. | 분할 전후 종목 총수량·원금·같은 시세 기준 평가액을 대조한다. 차이는 근거와 함께 확인한다. 동일 자료 재적용 후 중복이 없고 기존 통합 이력과 매도 통계가 보존된다. |

## 구현 시 참고할 기존 코드

- 보유자 기본값·추론과 중복 등록 조건은 [보유자 모델](../types/owner.ts), [로드 시 보유자 보완](../utils/portfolioCalculations.ts), [자산 등록](../components/AddNewAssetModal.tsx)에서 확인한다.
- 현재 표와 카드에 공통으로 적용할 그룹 계산은 순수 함수로 두고 [포트폴리오 화면](../components/layouts/PortfolioView.tsx), [데스크톱 행](../components/portfolio-table/PortfolioTableRow.tsx), [모바일 카드](../components/portfolio-table/PortfolioMobileCard.tsx)에서 사용한다.
- 현재 추가매수는 평단·수량과 메모를 갱신한다. 매도는 전량 매도 시 잔고 행을 제거한다. 거래기록 확장은 [매수·매도 계산](../utils/assetMutations.ts), [거래 처리 훅](../hooks/useAssetActions.ts), [매도기록 통합](../utils/sellRecords.ts), [포트폴리오 저장](../hooks/usePortfolioData.ts) 경로에 함께 적용한다.
