# 카카오톡 알림 설정 가이드 (사용자용)

> 이 문서는 "설정 → 카카오톡 알림"에 있는 1회 설정 가이드(체크리스트)의 상세판입니다.
> 화면 안내만으로 막히면 이 문서를 참고하세요. 모든 단계는 되돌릴 수 있습니다.
>
> 먼저 알아둘 것: 카톡은 손절선·익절선·불타기선을 **개장 중 매시간**(±15분), 추세선 이탈은
> **마감 확정 종가로 하루 1회** 알려줍니다. **카톡은 알려줄 뿐 대신 팔아주지 않습니다** —
> 손절은 증권사 예약주문이 먼저이고, 카톡은 확인 채널입니다.
>
> **2026-09-26부터**: "보유종목 터틀"(팔 때·다시 살 때·추가 매수·손절 이탈) 알림도 같은 카톡으로
> 옵니다 — 시장별 마감 확정 후 1회 + 아침 요약 1회. 매매 계획을 따로 안 세운 종목도 대상입니다
> (터틀 화면에서 보이는 그대로가 카톡으로 옵니다).

---

## 준비물

- 이 저장소를 내려받은 PC(터미널에서 `npm run gas:push`를 실행할 수 있어야 합니다)
- Google 계정(Drive와 동일 계정을 권장 — Apps Script·Drive 파일 생성에 쓰입니다)
- 카카오 계정

---

## ① 카카오 개발자 앱 만들기

1. [Kakao Developers](https://developers.kakao.com) 접속 → 로그인 → **애플리케이션 추가하기**.
2. 앱 이름은 아무거나(예: "자산관리 알림"). 회사명도 개인용으로 아무거나 입력해도 됩니다.
3. 생성된 앱 → **제품 설정 → 카카오 로그인** → 활성화 설정을 **ON**.
4. **카카오 로그인 → 동의항목** → `[접근권한] 카카오톡 메시지 전송(talk_message)` 항목을
   **설정함(필수 동의)** 또는 **설정함(선택 동의)** 으로 바꿉니다.
5. **[앱] → [플랫폼 키] → REST API 키** 화면에서 **REST API 키** 값을 복사해 둡니다 → 이후 `KAKAO_REST_KEY`로 사용합니다.
6. Redirect URI는 ②에서 웹앱을 배포한 뒤 다시 돌아와 등록합니다(지금은 비워 둬도 됩니다). 등록 위치는
   **[카카오 로그인] 메뉴가 아니라 이 REST API 키 화면 안의 [카카오 로그인 리다이렉트 URI] 입력란**입니다
   (카카오 콘솔 개편으로 이 위치로 이동함 — 2026-09 기준).

**막히면 여기**: "카카오 로그인" 메뉴 자체가 안 보이면, 앱 요약 정보 화면에서 플랫폼(Web) 등록이
먼저 필요할 수 있습니다. 사이트 도메인은 실제 서비스가 아니라도 `https://script.google.com`처럼
아무 값이나 넣어도 통과합니다(Redirect URI만 정확하면 됩니다).

## ② 스크립트 배포 (Google Apps Script)

1. 터미널에서 이 저장소 루트로 이동한 뒤(`npm install`을 아직 안 했다면 먼저 실행 — `@google/clasp`가
   devDependency로 설치되어 있어야 `npx clasp`가 동작합니다):
   ```
   npm install
   npx clasp login
   ```
   브라우저가 열리면 Google 계정으로 로그인·권한 승인합니다(최초 1회).
2. [script.google.com](https://script.google.com)에서 **새 프로젝트**를 만들고, 프로젝트
   설정(⚙️)에서 **스크립트 ID**를 복사합니다.
3. 저장소 루트의 `.clasp.json.example`을 `.clasp.json`으로 복사하고, `scriptId`에 방금 복사한
   값을 붙여 넣습니다(`rootDir`은 이미 `scripts/notify/gas/dist`로 맞춰져 있습니다).
4. 스크립트를 빌드해 올립니다:
   ```
   npm run gas:push
   ```
   (내부적으로 `npm run gas:build`로 `scripts/notify/gas/dist/`를 만든 뒤 `clasp push`합니다.)
5. Apps Script 편집기(script.google.com)에서 **배포 → 새 배포**:
   - 유형: **웹앱**
   - 실행: **나(Execute as: Me)**
   - 액세스 권한이 있는 사용자: **모든 사용자(Anyone)**
6. 배포 후 나오는 **웹앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사해 둡니다.
7. ①로 돌아가 Kakao Developers의 **Redirect URI**에 이 웹앱 URL을 정확히 등록합니다(끝의 `/exec`
   까지 포함, 오타 없이).

**막히면 여기**: `npx clasp login`에서 `npm error could not determine executable to run`이 뜨면
`@google/clasp`가 아직 설치되지 않은 것입니다 — 저장소 루트에서 `npm install`을 한 번 실행한 뒤
다시 시도하세요.

코드를 고쳐서 재배포(새 버전 배포)하면 URL이 바뀔 수도, 안 바뀔 수도 있습니다
(같은 배포를 "관리 → 편집"으로 갱신하면 URL 유지, "새 배포"를 또 만들면 새 URL). URL이 바뀌면
①의 Redirect URI와 앱 설정의 웹앱 URL을 모두 다시 맞춰야 합니다.

## ③ 열쇠 입력 + 트리거 설치

1. Apps Script 편집기 → 왼쪽 **프로젝트 설정(⚙️)** → **스크립트 속성** → **속성 추가**.
2. 다음을 추가합니다(카카오 계정 생성 시점에 따라 REST API 키의 "클라이언트 시크릿"이 기본
   활성화돼 있을 수 있어, 세 번째 속성이 필요할 수 있습니다).
   | 속성 | 값 |
   |---|---|
   | `KAKAO_REST_KEY` | ①에서 복사한 REST API 키 |
   | `SHARED_SECRET` | 임의로 정한 긴 문자열(비밀번호처럼). ⑤에서 앱 설정에도 **똑같이** 입력합니다 |
   | `KAKAO_CLIENT_SECRET` | (필요한 경우만) Kakao Developers → **[앱] → [플랫폼 키] → REST API 키 → [클라이언트 시크릿]**에서 [활성화]가 ON이면 표시되는 코드값을 복사 |
3. 왼쪽 **편집기**로 돌아가 함수 선택 드롭다운에서 `installTriggers`를 고르고 **실행**을 누릅니다.
4. 최초 실행 시 권한 승인 화면이 뜹니다. 본인 계정·본인 스크립트이므로 "고급 → ○○(안전하지
   않음)으로 이동"을 눌러 진행해도 됩니다.
5. 실행 로그에 오류가 없으면 완료입니다 — `hourlyCheck`/`closeCheck`가 매시간, `morningDigest`가
   매일 07시대에 자동으로 돕니다.

**막히면 여기**: 실행 권한 화면이 계속 안 뜨면 브라우저 팝업 차단을 확인하세요. 트리거를 다시
설치하고 싶으면 `installTriggers`를 다시 실행하면 됩니다(기존 관리 트리거를 정리하고 새로 만듭니다).

## ④ 카카오 1회 동의

1. 브라우저 주소창에 `<웹앱 URL>?action=kakao-auth`를 입력해 엽니다.
2. 카카오 로그인 화면이 뜨면 로그인 → **동의하고 계속하기**.
3. "연결됨"이라는 안내가 뜨면 완료입니다.

이후로는 브라우저 개입이 필요 없습니다. 액세스 토큰은 매 실행마다 자동 갱신되고, 새 리프레시
토큰이 오면 저장 성공을 확인한 뒤에만 다음 단계로 진행합니다(저장 실패 시 락아웃을 막기 위한
안전장치입니다).

**막히면 여기**:
- **"등록되지 않은 Redirect URI" 오류** → ①의 Redirect URI가 지금 접속한 웹앱 URL과 정확히
  같은지(오타·끝의 `/exec` 포함) 확인하세요.
- **"설정 필요" 페이지가 뜸** → ③에서 `KAKAO_REST_KEY` 스크립트 속성을 저장했는지 확인하세요.

## ⑤ 앱에 연결

1. 앱 → **설정 → 카카오톡 알림**로 이동합니다.
2. **웹앱 URL**에 ②에서 복사한 주소를 붙여 넣습니다.
3. **공유 시크릿**에 ③에서 정한 `SHARED_SECRET` 값을 똑같이 입력합니다.
4. **연결 테스트** 버튼을 누릅니다 → 잠시 후 카카오톡 "나에게 보내기"로 테스트 메시지가 오면
   성공입니다.
5. **지금 동기화** 버튼을 누릅니다 → 현재 활성 매매 계획이 GAS로 전달됩니다.
6. 필요하면 **자동 동기화**(계획이 바뀌면 5초 뒤 자동 전송)와 **불타기 알림**(기본 꺼짐 —
   불타기는 검증되지 않은 기능입니다) 토글을 켭니다.

웹앱 URL·공유 시크릿은 **이 브라우저(localStorage)에만** 저장되고 Google Drive 동기화에
포함되지 않습니다 — 다른 기기·다른 브라우저에서는 ⑤를 다시 해야 합니다.

## 문제 해결 FAQ

**Q. `npx clasp login`이 `npm error could not determine executable to run`으로 실패해요.**
A. `clasp`가 로컬에 설치되어 있지 않은 상태입니다. 저장소 루트에서 `npm install`을 실행해
`@google/clasp`(devDependency)를 설치한 뒤 다시 `npx clasp login`을 실행하세요.

**Q. "연결 실패 — 카카오 토큰 교환 실패 (401): invalid_client / Bad client credentials (KOE010)"가 떠요.**
A. 카카오 앱의 REST API 키에서 **클라이언트 시크릿**이 활성화돼 있는데 `KAKAO_CLIENT_SECRET`
   스크립트 속성을 안 넣은 경우입니다. Kakao Developers → **[앱] → [플랫폼 키] → REST API 키 →
   [클라이언트 시크릿]**에서 코드를 복사해 ③의 스크립트 속성에 `KAKAO_CLIENT_SECRET`으로 추가한
   뒤, ②처럼 재배포하고 ④를 다시 진행하세요.

**Q. redirect_uri 불일치 오류가 계속 떠요.**
A. Kakao Developers의 Redirect URI와 실제 웹앱 URL(`.../exec`)이 문자 하나까지 같아야 합니다.
   `http`/`https`, 끝의 슬래시 유무까지 정확히 맞추세요. 웹앱을 재배포해 URL이 바뀌었다면
   Redirect URI도 새 URL로 갱신해야 합니다.

**Q. 웹앱을 재배포했더니 앱 설정에서 연결 테스트가 실패해요.**
A. "새 배포"를 만들면 URL이 바뀔 수 있습니다. Apps Script의 배포 목록에서 URL을 다시 확인해
   앱 설정의 웹앱 URL을 갱신하세요. 기존 배포를 "관리 → 이 배포 편집"으로 코드만 갱신하면
   URL이 유지됩니다.

**Q. 토큰이 만료됐다는 메일이 왔어요 / 오랫동안 알림이 안 와요.**
A. 카카오 리프레시 토큰은 2개월 동안 유효하고 매 실행마다 자동 갱신되므로, 매일 정상적으로
   실행되고 있다면 사실상 만료되지 않습니다. 다만 스크립트를 오래(2개월 이상) 멈춰 뒀다가
   다시 켜면 토큰이 만료돼 있을 수 있습니다 — 이 경우 ④(카카오 1회 동의)를 다시 하세요.

**Q. 실패했다는 메일이 왔어요.**
A. 발송/토큰갱신/시세조회 실패 시 최대 하루 1회 본인 이메일로 알림이 갑니다. Apps Script
   편집기의 **실행 기록**(왼쪽 시계 아이콘)에서 어떤 함수가 왜 실패했는지 자세한 로그를
   확인할 수 있습니다.

**Q. 발송이 너무 많이/적게 와요.**
A. 하루 발송 상한은 8건이며, 초과분은 요약 1건으로 묶입니다. 밤 12시~오전 7시(정숙시간)에는
   발송을 보류했다가 아침 07시대에 모아서 보냅니다. 불타기 알림은 기본적으로 꺼져 있습니다.

## 이미 설정하신 분 — "보유종목 터틀" 알림 추가 안내 (2026-09-26)

①~⑤를 이미 마치셨다면 새로 처음부터 할 필요는 없습니다. 아래 순서만 진행하세요.

1. **`npm run gas:push`** — 터미널에서 저장소 루트로 이동해 실행합니다(빌드 후 자동으로 배포까지
   됩니다). 새 배포를 또 만들 필요는 없습니다 — 기존 배포가 자동으로 최신 코드로 갱신됩니다.
2. **앱에서 동기화** — 설정 → 카카오톡 알림 화면에서 "터틀 알림 포함 — 보유 N종목 · 감시 M종목..."
   문구가 보이는지 확인한 뒤 **지금 동기화** 버튼을 누릅니다(보유·감시 종목 정보가 GAS로 전달됩니다).
3. **트리거는 다시 설치할 필요 없음** — `hourlyCheck`/`closeCheck`/`morningDigest`는 그대로 쓰고,
   터틀 판정은 기존 `closeCheck`(마감 후 1회)·`morningDigest`(아침 요약) 안에 추가됐을 뿐입니다.
4. **테스트 발송** — 카카오톡 알림 설정 화면의 **연결 테스트** 버튼으로 카톡이 정상적으로 오는지
   확인하세요(터틀 전용 테스트 발송은 따로 없습니다 — 실제 신호는 다음 장마감/아침에 옵니다).
5. 터틀 화면(보유자산 표·홈 "터틀 오늘 할 일")에서 감시 등록한 관심종목·재매수 포지션이 정확히
   보이는지 한 번 확인하면 준비 끝입니다.

**참고**: 터틀 알림은 매매 계획(TradePlan)과 하루 발송 상한(8건)·정숙시간·요약 묶음을 그대로
공유합니다 — 알림이 몰리는 날에는 요약 1건으로 묶여 올 수 있습니다.
